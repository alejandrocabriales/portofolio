# Personal Portfolio

A modern, Notion-inspired personal portfolio website built with Astro and Tailwind CSS. This project showcases my work, skills, and professional journey in a clean, minimalist design that takes inspiration from Notion's aesthetic.

## 🎨 Design Philosophy

- Clean, minimalist interface inspired by Notion's design language
- Focus on typography and whitespace
- Dark mode support
- Responsive design for all devices
- Smooth animations and transitions

## 🚀 Tech Stack

- [Astro](https://astro.build) - Modern static site builder
- [Tailwind CSS](https://tailwindcss.com) - Utility-first CSS framework
- TypeScript - For type safety and better developer experience

## 📁 Project Structure

```text
/
├── public/          # Static assets
├── src/
│   ├── components/  # Reusable UI components
│   ├── layouts/     # Page layouts
│   ├── pages/       # Astro pages
│   └── styles/      # Global styles and Tailwind config
└── package.json     # Project dependencies
```

## 🛠️ Development

1. Clone the repository
2. Install dependencies:
   ```bash
   npm install
   # or
   pnpm install
   ```

3. Start the development server:
   ```bash
   npm run dev
   # or
   pnpm dev
   ```

4. Build for production:
   ```bash
   npm run build
   # or
   pnpm build
   ```

## 🔍 SEO

Identity, canonical origin and social defaults live in `src/config/site.ts`. That
file is the only place a domain, name or profile URL should ever be typed.

| Surface | Where it lives |
| :-- | :-- |
| Head metadata (canonical, OG, Twitter, robots, icons) | `src/components/seo/Seo.astro` |
| JSON-LD `@graph` (Person, WebSite, WebPage, BlogPosting, BreadcrumbList) | `src/lib/schema.ts` |
| Per-route SEO props | each page, passed into `src/layouts/Layout.astro` |
| Sitemap priorities and post `lastmod` | `astro.config.ts` |
| Build-time validation | `integrations/seo-validate.ts` |
| IndexNow submission | `integrations/indexnow.ts` |
| Agent-facing copies | `src/pages/llms.txt.ts`, `src/pages/blog/[slug].md.ts` |
| Corpus structured data | `src/pages/schema/site.json.ts`, `src/pages/schemamap.xml.ts` |

### Social cards must be regenerated by hand

```bash
pnpm og
```

Cards and raster icons are **committed**, not built. `sharp` rasterises text
through the operating system's fonts, so the same SVG renders differently in CI
than it does locally — generating at build time would mean nobody ever reviews
what actually ships. Run `pnpm og` and commit the PNGs after adding a post,
adding a project, or changing the name or role in `src/config/site.ts`.

A page with no card of its own silently falls back to `/og/default.png`, so a
forgotten run degrades rather than breaks.

### The build fails on broken SEO

`seo-validate` walks the built HTML and errors on a missing `<title>`, a missing
description or unparseable JSON-LD. It warns — without failing — on duplicate
titles, a page without exactly one `<h1>`, images with no `alt`, an indexable
page with no canonical, internal links with no target in the build, and titles
or descriptions outside SERP bounds.

Post frontmatter is bounded at the source too: `src/content.config.ts` rejects a
title over 70 characters or a description over 160, because both are copied
verbatim into the `<head>` and both get cut mid-word in a result.

### Not automatable

- Verify the site in [Google Search Console](https://search.google.com/search-console) and [Bing Webmaster Tools](https://www.bing.com/webmasters), and submit `/sitemap-index.xml` to both. IndexNow reaches Bing, Yandex, Seznam and Naver; it does not reach Google.
- IndexNow only fires on Netlify production builds (`CONTEXT=production`). Rotating the key means changing `SITE.indexNowKey` and renaming `public/<key>.txt` in the same commit.

## 🚀 Project Structure

Inside of your Astro project, you'll see the following folders and files:

```text

├── public/
│   └── favicon.svg
├── src/
│   ├── layouts/
```

To learn more about the folder structure of an Astro project, refer to [our guide on project structure](https://docs.astro.build/en/basics/project-structure/).

## 🧞 Commands

All commands are run from the root of the project, from a terminal:

| Command                   | Action                                           |
| :------------------------ | :----------------------------------------------- |
| `npm install`             | Installs dependencies                            |
| `npm run dev`             | Starts local dev server at `localhost:4321`      |
| `npm run build`           | Build your production site to `./dist/`          |
| `npm run preview`         | Preview your build locally, before deploying     |
| `npm run og`              | Regenerate social cards and icons into `public/` |
| `npm run astro ...`       | Run CLI commands like `astro add`, `astro check` |
| `npm run astro -- --help` | Get help using the Astro CLI                     |
